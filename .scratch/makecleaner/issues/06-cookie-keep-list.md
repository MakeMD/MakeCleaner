# 06: Cookie keep-list

**What to build:** в Options → Cookies два списки: «Cookies на комп'ютері» (домени з усіх браузерів) і «Зберегти». Користувач переносить домени між списками, імпорт/експорт списку. Під час чистки cookies видаляються всі, крім доменів зі списку «Зберегти» (видалення рядків у базах cookies браузерів, а не файлу цілком).

**Blocked by:** 05

**Status:** done

- [x] Домен зі списку «Зберегти» виживає чистку в Chromium і Firefox, решта видаляються
- [x] Збіг за доменом включно з піддоменами (.example.com)
- [x] Імпорт/експорт списку в текстовий файл
- [x] Тест на фікстурних SQLite-базах cookies

**Нотатки (done):**
- Пункт Cookies тепер завжди видаляє рядки (`cookies.host_key` у Chromium — `Network\Cookies` і старий `Cookies` у корені профілю; `moz_cookies.host` у Firefox), файл бази лишається. Порожній keep-list = видалити всі рядки.
- Збіг: `example.com` зберігає `.example.com`, `www.example.com` і будь-який піддомен, але не `badexample.com`; запис `www.example.com` нормалізується до `example.com`. Логіка — `Cookies.cs`.
- Список «Зберегти» — `KeepCookie1..n` в ini; читається через хук `Cookies.Keep`, який виставляє `Program` з Settings (щоб і GUI, і майбутній `/auto` тікета 11 бачили той самий список).
- «Cookies на комп'ютері» читається read-only; заблокована база (запущений браузер) читається з тимчасової копії, яку потім видаляємо.
- `WithDb` отримав `DefaultTimeout = 1`: без нього заблокована база чекала 30 с (стосувалось усіх SQLite-пунктів тікета 05).
- Імпорт/експорт: один домен на рядок, `#`-коментарі й порожні рядки ігноруються.
- GUI-смоук: `tools/guismoke-cookies.ps1` (фікстурні бази через Python sqlite3). Якщо запущений справжній Chrome/Firefox, смоук зупиняється після Analyze, бо Clean спитав би про закриття браузера; Run Cleaner у GUI на цій машині тому не прогонявся (покрито юніт-тестом на фікстурах).
