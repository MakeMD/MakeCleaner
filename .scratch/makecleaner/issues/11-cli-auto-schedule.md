# 11: CLI /auto і розклад

**What to build:** `MakeCleaner.exe /auto` тихо виконує Clean збереженим набором пунктів і завершується (опційно /shutdown). В Options користувач явно створює/видаляє задачу в Task Scheduler (раз, щодня, щотижня, при вході), яка викликає /auto. Жодних служб, Run-ключів чи фонових процесів.

**Blocked by:** 04

**Status:** done

- [x] /auto без вікна, код повернення 0 при успіху, лог результату (`MakeCleaner-auto.log` поруч з ini; 1 = збій, деталі в лозі)
- [x] Задача створюється лише кнопкою в Options і повністю видаляється кнопкою
- [x] Після видалення задачі в системі не лишається слідів MakeCleaner в автозапуску (перевірено: 0 задач, 0 Run-значень, 0 служб)

**Notes (done):**
- Prefactor: прохід «вибрані пункти → Analyze → Clean» винесено з `MainForm` у `CleanPass` — форма і `/auto` викликають один код (Custom-rule, excludes, вік 24 год, браузерні SQLite-дії, secure delete, Wipe Free Space).
- `/auto` бере збережені стани чекбоксів (`CleanPass.Saved`), Wipe Free Space ніколи; запущений браузер — пропускається без діалогу й без kill (у лозі `skipped running: …`). `/shutdown` — `shutdown /s /t 60` (можна скасувати `shutdown /a`).
- Задача: одна, `MakeCleaner Auto Clean` у корені планувальника, реєструється через COM з Task Scheduler XML (не залежить від локалі, на відміну від `schtasks /SD /ST`), від поточного користувача, InteractiveToken, LeastPrivilege, без збереження пароля. Типи: Once / Daily / Weekly (день тижня — з вибраної дати) / At sign-in.
- Перевірено: XML для всіх типів (тест), реєстрація+видалення всіх 4 типів справжнім планувальником під тестовим ім'ям з тригером через 5 років і неіснуючим exe (тест), наскрізний `/auto` справжнім exe в окремому процесі на фікстурі (тест + `tools/autosmoke.ps1`: без вікна, код 0, фікстура порожня, Wipe проігноровано).
- Не перевірено вживу: кнопки Create/Remove у GUI не натискались (створили б задачу зі справжнім ім'ям); `/shutdown` не запускався; спрацювання задачі за розкладом не чекали.
