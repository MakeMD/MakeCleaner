# 14: WPF-оболонка + екран Cleaner (tracer bullet)

**What to build:** новий WPF-застосунок MakeCleaner поверх Core. Вікно зі структурою класичного CCleaner (див. PLAN.md «Етап 2» і `re/notes/03-gui.md`), але з власним візуалом: ліве меню-плитки (Cleaner, Registry, Tools, Options), контент праворуч, тонкий футер з версією й About. Tools і Options поки показують порожню сторінку з вертикальним підменю (спільна частина, яку наповнять тікети 15–18). Екран Cleaner повністю робочий: вкладки Windows / Browsers / Applications над деревом чекбоксів (групи з тристаном, попередження для ризикованих пунктів), смуга прогресу з «NN% (x з y)» і Cancel, результати по категоріях (розмір, кількість) з перемикачем «Підсумок / Файли», контекстне меню (відкрити папку, додати в Exclude), Analyze ліворуч і Run Cleaner праворуч, діалог для запущеного браузера. Кольори й розміри — в одному ResourceDictionary. WinForms-застосунок поки лишається поруч.

**Нотатки (done):**
- `src/MakeCleaner.Wpf` → `MakeCleaner.Wpf.exe` (поруч із WinForms до тікета 19). Файли: `Program.cs` (той самий /auto), `Theme.xaml` (усі кольори/стилі), `MainWindow` (ліве меню-плитки, футер з версією й About), `SubNavPage` (підменю + сторінка; додати сторінку = `.Add("Назва", () => new View())`; Registry/Tools/Options поки порожні), `CleanerView`, `CheckNode` (тристан групи).
- Групи: галочка на групі вмикає лише безпечні пункти; ризиковані (з Warning) вмикаються тільки власною галочкою з попередженням. Якщо всі безпечні вже ввімкнені, клік по групі знімає все — інакше група застрягла б у третьому стані.
- Результати: «Підсумок» — рядок на кожен ввімкнений пункт, що щось знайшов (`CleanPass.Summary`, файл, спільний для двох правил, рахується раз); «Файли» — до 5000 рядків файлів + реєстр + дії + рядки браузерів. Контекстне меню: відкрити папку, додати файл/папку в Exclude (той самий список, що Options; файл одразу випадає з поточного проходу).
- Cancel — кнопка в смузі прогресу, активна лише під час Analyze. Дерева під час Analyze/Clean лишаються активними: галочки вже зчитані, а вимкнення сотень чекбоксів засипало б скрінрідери UIA-подіями (виміряно: ~2 с на клік).
- Версія переїхала в `Directory.Build.props` (одне місце для обох застосунків; `release.ps1` читає її як і раніше).
- Смоуки: `guismoke.ps1`, `guismoke-apps.ps1`, `guismoke-browsers.ps1` отримали `-Wpf` (дефолт — WinForms); очікування вікна 20 с (холодний старт WPF буває >10 с). Новий `tools/guismoke-wpf.ps1`: тристан групи, Cancel посеред Analyze (фікстура 40k файлів у 4000 папках), Підсумок/Файли, `/auto` з WPF-exe на фікстурі. `releasecheck.ps1` його поки пропускає (у zip ще WinForms-exe).
- Не перевірено вживу: діалог попередження ризикованого пункту й діалог запущеного браузера (модальні вікна, смоуки їх не відкривають); «Відкрити папку»/«Exclude» з контекстного меню; DPI-масштабування на моніторі з іншим масштабом.
